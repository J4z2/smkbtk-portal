# SMK Bandar Tasik Kesuma Portal — v12 source code

The original v12 HTML prototype, separated into editable HTML, CSS and JavaScript. Its existing design, Malay interface copy, demo records and application logic are preserved. No installation, build step, server or internet connection is required.

## Run the portal

1. Extract the entire ZIP into a folder.
2. Open **index.html** in a modern desktop browser, such as Chrome or Edge.
3. Choose a login role. The default demo email and password are already filled in.

Keep `index.html`, `styles.css` and `app.js` together. Open the extracted file, rather than viewing a file inside the ZIP. After editing a file, save it and refresh the browser.

There are no required external assets or third-party runtime libraries. Graphics use CSS, inline SVG and text/emoji. Uploaded student photos are stored as data URLs in browser data.

## Editing guide

- **Landing page or login layout:** edit `index.html`. Most dashboard content is generated by the functions in `app.js`, rather than being written directly into the empty view containers.
- **Colours, spacing, typography and responsive layout:** edit `styles.css`. Start with the `:root` variables. Keep the existing rule order because later rules intentionally override earlier ones.
- **Demo records and school details:** edit `seed`, `FORM_CLASS_BLUEPRINTS` and `migratePortalData()` near the start of `app.js`. Existing saved browser data can take precedence over your seed edits; reset and reload to see fresh demo data.
- **Parent, teacher or admin screens:** find `renderParent()`, `renderTeacher()`, `renderSuper()` and their corresponding `*Html()` functions in `app.js`.
- **COEx, Gear and intervention behaviour:** find `defaultCoexRules()`, `assessmentProfile()`, `parentCoexHtml()`, `teacherCoexHtml()`, `superCoexHtml()` and `riskProfile()`.
- **Save/load behaviour:** see `KEY`, `load()`, `data()`, `save()` and `resetDemo()`.

Section comments in `app.js` provide a navigation guide. Existing element IDs and inline event handlers are retained. Keep `app.js` as a classic script at the end of the HTML body: changing it to a module or wrapping all functions in a private scope would break the inline handlers.

Inline styles in HTML and generated templates are intentionally retained where the original prototype uses them, including data-dependent colours and layout. HTML template strings remain close to the original to avoid changes in rendered whitespace.

Optional: the code was formatted with Prettier 3.6.2. The included settings preserve quoted object keys and avoid reformatting embedded HTML strings; using Prettier is not required to run or edit the portal.

## Data and reset

All changes stay in this browser's `localStorage`, under the original key `smk-seri-bestari-coex-v7-fixed`. They are not sent to a server or shared across devices. Login state is kept in memory, so sign in again after refreshing.

A different browser, profile, folder location or local hosting origin may have a different saved dataset. Renaming this storage key in `app.js` starts a separate demo dataset. Browsers can limit or clear storage for local files, and private browsing can discard saved changes.

Use the prototype's **Reset demo** control to restore its seed records, then **reload the page** to restore the complete Tingkatan 1–6 migration. Export anything you want to keep before resetting. The existing JSON export is a snapshot; this prototype does not include JSON restore. Its separate CSV import adds student records.

This is a frontend demonstration with browser-only login and storage. Backend services, real authentication, multi-user synchronisation and production PDF generation are outside this package.
